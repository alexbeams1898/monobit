# Drawing sprites

You draw a 1-bit PNG in any pixel-art tool. A small Python script
(`scripts/png_to_sprite.py`) converts it into the byte array the engine
expects. You either commit the bytes yourself, or paste the converter's
output into a chat with the assistant.

## Recommended tool: Aseprite

You already have it. One-time setup:

1. **File → New** with the *exact* dimensions you want (e.g. 8×12 for the
   player, 5×8 for an enemy). Set Color Mode to **Indexed**.
2. **Window → Palettes** → reduce the palette to two entries: pure black
   `(0,0,0)` and pure white `(255,255,255)`. This prevents accidental
   greys.
3. Draw with the pencil tool. White = pixel on, black = pixel off.
4. **File → Export Sprite Sheet** (or just **Save As**) → save as `.png`.

### Aseprite tips for tiny sprites

- Zoom to 800–1600% (`+` key) — at 1× you can't see individual pixels.
- Turn on the pixel grid: **View → Show → Pixel Grid**.
- Symmetry mode (toolbar) is gold for symmetric sprites — set it to
  vertical mirror down the middle and you only have to draw one half.

## Streamlined workflow with make targets

Two-step loop, no manual Python invocations:

```bash
make sprite NAME=player W=8 H=12     # opens Aseprite on a blank 8x12 canvas
# ... draw, then Ctrl+S in Aseprite ...
make sprite-convert NAME=player      # prints the byte array
```

Files land in `art/<name>.png` (gitignored — the bytes in `sprites.cpp`
are the source of truth).

## Convert the PNG (manual)

If you'd rather invoke the converter directly:

```bash
python scripts/png_to_sprite.py path/to/sprite.png --name PLAYER
```

Output goes to stdout — paste it directly into `games/rpg/sprites.cpp`.
The `--name` flag controls the array's symbol prefix.

Example output:

```cpp
// 8x12 sprite (auto-generated by scripts/png_to_sprite.py)
const u8 PLAYER_data[16] PROGMEM = {
    // page 0 -- rows 0..7
    0xC3, 0xE6, 0xF8, 0xFC, 0xFC, 0xF8, 0xE6, 0xC3,
    // page 1 -- rows 8..11
    0x01, 0x0F, 0x0F, 0x03, 0x03, 0x0F, 0x0F, 0x01,
};
// In sprites.cpp's tables:
//   widths[PLAYER]  = 8
//   heights[PLAYER] = 12
```

When replacing an existing sprite, you only need the inside of the array.
When adding a new sprite, also update `widths[]`, `heights[]`, and the
`Id` enum in `sprites.h`/`sprites.cpp`.

## Format reference

The engine expects sprites stored **page-major within column-major**:

- A "page" is an 8-row band (one byte per column within that band)
- For a sprite of width `W` and height `H`:
  - bytes per column = `ceil(H / 8)`
  - total bytes      = `W * ceil(H / 8)`
  - storage order    = page 0 of all columns left-to-right, then page 1 of
    all columns, etc.
- Within a byte, **bit 0 = topmost row** of that page, bit 7 = bottom row.

So an 8×12 sprite is 16 bytes: 8 for rows 0-7, then 8 for rows 8-11
(only bits 0-3 of those second-page bytes are used).

The width hard-cap is **16 px** because `draw_progmem_sprite` uses a
16-byte stack scratch buffer per page. Wider sprites need a bigger buffer
in `game.cpp`.

## Workflow with the assistant

If you'd rather not run the script yourself: draw the sprite, drop the
PNG path into the conversation, and the assistant can run the converter
and commit the result for you.
