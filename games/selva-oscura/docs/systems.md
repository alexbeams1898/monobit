# Selva Oscura -- Systems Index

> **Purpose:** one-line-per-system map of what exists, who owns what, and where to read for intent. Read this BEFORE designing a new system (per `.claude/CLAUDE.md` audit-discipline rule). If a relevant entry exists, read the header it points to before proposing anything.
>
> **Maintenance:** append a new line every time a real system ships. Cheap. Pays for itself the next time anyone audits for adjacent infrastructure. The cost of staleness is "the same system gets designed twice" -- which is what this file exists to prevent.
>
> **Sort order:** roughly bottom-up (engine layer → world → gameplay → UI). Within a layer, alphabetical. Each line: `**name**` — what it is — `path/to/header.h`.

## Application + persistence

- **SaveManager** — JSON save/load, schema-versioned, addCharacter / deleteCharacter — [include/SaveManager.h](../include/SaveManager.h)
- **selva::lang** — language map. Player-facing strings live in `config/lang/*.json` as tiered entries (`tier_0` default, `tier_1` / `tier_2` reveals gated on insight nodes). `selva::lang::resolve(key)` returns the highest-unlocked-tier text. See `docs/design/insight_revelation_system.md` *Implementation status*. — [include/lang/Language.h](../include/lang/Language.h)
- **selva::insight** — insight graph. Nodes in `config/insight/*.json`; each carries one trigger (`flag_set` / `dialog_began` / `examined` / `kill_count` / `sangue_accumulated`). `selva::insight::tick()` runs per frame, fires unlocked nodes into the active profile's `unlocked_insights`. `selva::lang` reads `hasInsight(node)` for tier promotions — the two modules share one node-id namespace and form ONE architecture. Event-source hooks: `notifyDialogBegan` (in `dialog::begin`), `notifyExamined` (in examine on_interact), `notifyKill` (in `fireEnemyDeath`). — [include/insight/Insight.h](../include/insight/Insight.h)
- **Tunables** — hot-reloadable balance numbers (walk_speed, accel, lockon yaw rates, AI tick hz, …) — [include/Tunables.h](../include/Tunables.h)
- **debug::Flags** — SESSION-ONLY diagnostic toggles (ai_perception overlay, footstep_log, physics_log, enemy_lifecycle, …). Kept distinct from Tunables: ships separate, never serialized, F1 panel renders under a distinct "Debug" section — [include/debug/Flags.h](../include/debug/Flags.h)
- **Formulas** — HP / poise / stamina formula registry — [include/Formulas.h](../include/Formulas.h)
- **WallClock** — single `wallClock()` time source used by everything (animations, cooldowns, scripted events) — [include/WallClock.h](../include/WallClock.h)
- **Scene (cinematic)** — time-bounded moment that locks input categories (combat / movement / look) while something plays out — `begin({combat:true, movement:true, look:false})` / `end()` / `active()` — used by wake-scene at game start, designed for the Guide-stepping-out moment too — [include/Scene.h](../include/Scene.h)

## Gameplay

- **Actor (unified PC/NPC model)** — pos, yaw, sampler, faction, is_boss, is_npc, boss_state, perception, hp/poise/stamina, action_state, appearance, spawn_decl_id — [include/gameplay/Actor.h](../include/gameplay/Actor.h)
- **Appearance** — per-actor visual parameters driving the figura umana doctrine: one humanoid rig, deformed per being. Universal across cosmologies — damned shades, the Unburdened Vagrant, the Guide, the keepers, divine emissaries all read their body shape from this schema; the burdened/unburdened distinction is cosmological state, not visual. Shipped axes: `body_type` enum (humanoid_male / humanoid_female skeleton bundle), uniform `body_scale`, per-channel `color` (Souls-convention [0,1] RGB), per-bone scales (`head_scale` / `arm_scale` / `leg_scale` / `torso_scale`), and per-vertex `morph_weights` map (glTF morph targets surviving from MPFB2 shape keys). Loaded from `config/characters/<name>.json`. Both PlayerProfile and EnemyArchetype carry an `character_path` field — the player gets the per-character variant (driven by future character designer), every enemy instance of an archetype shares the archetype's authored appearance (e.g. `larva_fresh.json`, `larva_aged.json`). Threaded through `buildActorModelMatrix(... body_scale)` so renderer + hurtbox + hitbox + lock-on reticle all read the same scaled transform from a single source of truth. `applyActorClipHipDelta` scales the world-delta by the same factor so a 0.85x body's world motion equals its visible foot motion (per `feedback_hip_delta_two_sides`). **`resolveAppearance(actor, now_wc)`** (in PerFrameTick.cpp) returns the LIVE Appearance, interpolating the whole struct between the actor's archetype appearance and `archetype->transform_target_archetype`'s appearance over the arrival-wait period — used today for fresh→aged larva burns. **Incoming generalization (per character-canvas.md *The AppearanceTransform primitive*):** the single `transform_target_archetype` lerp grows into `Appearance.transforms: vector<AppearanceTransform>` (each entry = id + source_kind + target_snapshot_path + strength). `resolveAppearance` → `resolveLiveAppearance` walks the vector, composing base + sum(transform_i.strength * delta_toward(target_i)). A new `AppearanceTransformWriter` subsystem per-frame-reconciles the transforms list against registered TransformSources owned by triggering systems (SangueSystem, EvolutionSystem, etc.). Snapshot files live at `config/characters/transforms/<id>.json` and contain only the axes that transform touches. Design + philosophy: [docs/design/character-canvas.md](design/character-canvas.md). — [include/gameplay/Appearance.h](../include/gameplay/Appearance.h)
- **AppearanceTransformWriter** *(incoming)* — per-frame reconciler over a process-wide registry of TransformSource entries. Each source declares an `active(actor)->bool` predicate, a `strength(actor)->float` function, and a `target_snapshot_path`. The reconciler rebuilds `actor.appearance.transforms` per-frame as a pure derivation from world state (flags + stats); no accumulated state, no push/pop mismatches, save/load restores trivially. Systems register their sources at boot. — `include/gameplay/AppearanceTransformWriter.h` *(not yet created)*
- **Faction** — `Faction` enum (Player / Hostile / Neutral / Allied) + `factionsHostile()` damage rule + **`Form` enum** (UnjudgedSoul / DamnedSoul / Animal / HellMachinery / Divine — cosmological category, drives stat-spread defaults and the Wood combat-permission doctrine) — [include/gameplay/Faction.h](../include/gameplay/Faction.h)
- **applyFormDefaults** — per-form Body/Stats baselines applied at spawn BEFORE archetype overrides. Sit at [src/gameplay/Actor.cpp](../src/gameplay/Actor.cpp). Tuned numbers in code; archetype `max_hp_override` etc. layer on top.
- **Enemies / spawn pipeline** — `spawnEnemyFromDecl`, `tickEnemies` (per-frame tick), `applyEnemyHitReact`, `fireEnemyDeath`, `tickPendingAttackSpawns` (windup deferred-spawn). Helper `actorByDeclId(id)` is the canonical actor-by-id lookup; centralizes the dozen interactable/scripted-event/HUD callsites that need it — [include/gameplay/Enemies.h](../include/gameplay/Enemies.h)
- **FlowSpawner** — declarative spawn flows from `config/spawn_flows/*.json`: initial populations (per-slot positions/yaws/archetypes/on_arrival_actions), trickle spawns up to an `active_cap`, scripted paths via `scripted_target_pos` + `waypoints`, slot-mode (`first_vacant_slot`) for queue/feeder layouts, on_arrival actions (`halt`, `convert_to:<archetype>`, `despawn`). Each spawn stamps `actor.spawning_flow_id` so `tickArrivals` matches by flow rather than archetype id (two flows sharing an archetype don't collide) — [include/spawn/FlowSpawner.h](../include/spawn/FlowSpawner.h)
- **Interaction** — Press-E system: each registered `Decl` has a `Kind`, `position`-closure, `range_meters`, `on_interact` callback, optional `available` gate. Per-frame closest-target pick. Archetype-driven Talk (NPC) and Examine (mob with `examine_text`) interactables auto-register on spawn; range from `archetype.interact_range_meters` — [include/interact/Interaction.h](../include/interact/Interaction.h)
- **ItemRegistry / Inventory** — items declared in `config/items/*.json`, categories in `config/items/categories/`, runtime inventory per-character — Elden-Ring tabbed model: infinite total capacity, per-`ItemDef` `max_carry`, overflow auto-routes to Wood-side chest. **No `Money` category** (sangue is HUD, not inventory). **New `Incant` category** (Unburdened combat verb; class-pickers may learn). **Unarmed is a weapon** — every character carries one `unarmed` `ItemInstance` from game-start, equipped to `Equipment.unarmed`, gains XP per kill, class scaling differentiates. Also exposes `craftAndRecord(recipe)` — the post-craft hook that increments `PlayerProfile.craft_counts[recipe]`, checks the recipe's `unlock_after` threshold, and appends `unlocks_recipe` to `known_recipes` on cross. Design: [docs/design/inventory.md](design/inventory.md) — [include/items/ItemRegistry.h](../include/items/ItemRegistry.h)
- **UseHandlers (selva::items)** — string-keyed dispatch for the inventory Use button. ItemDef declares `"use_handler": "<key>"` in its JSON; selva-side modules call `registerUseAction(key, fn)` at boot to provide the implementation. Per-item gate via `use_condition`. Today's registrations: `"heal_consumable"` (HealHandlers.cpp). — [include/items/UseHandlers.h](../include/items/UseHandlers.h)
- **HealHandlers (selva::items)** — registers the `heal_consumable` Use-action. Dispatches on item config_path to the formulas.json heal_pct table (Poultice 20% / Salve 35% / Electuary 55% / Theriac 80% of max HP), applies the % to player HP, and consumes one. Surfaces: the inventory Use button + the quick-slot Q hotkey (via `selva::combat::useprimed`). HealHandlers is purely a USE-handler module; the hotkey-dispatch lives in QuickSlot. Per [[project_healing_system_locked_2026_06_14]]. — [include/items/HealHandlers.h](../include/items/HealHandlers.h)
- **QuickSlot (selva::combat)** — Souls/ER consumables-wheel, in-fiction called the **Scrip** (the pilgrim's pouch). Per-character rotation of `<= kQuickSlotCapacity` (=5) consumable config_paths plus a `primed_index`. **Q** uses the primed item (`useprimed` looks up an instance in inventory, fires its `use_handler` through the generic UseHandlers pipeline, which orchestrates consume-on-fired + toast). **X / Shift+X** cycle primed forward / backward. Assignment by config_path (not ItemInstanceId) so the slot survives crafting new instances of the same item type. Two assignment APIs: `assignToQuickSlot(path)` appends to the next free slot (used by the auto-assign-on-grant hook); `setQuickSlot(index, path)` writes to a specific slot (used by the Borne sub-page's Scrip TreeNode). Persists across save/load. Settings toggle `auto_assign_consumables_to_quick_slot` (off by default) auto-appends newly-discovered consumables to an empty slot. — [include/combat/QuickSlot.h](../include/combat/QuickSlot.h)
- **Weapon XP** — per-`ItemInstance` progression: `weapon_xp_level` + `weapon_xp_current` + `evolution_bonus`. Cosmologically = continued sangue installation into the weapon's imprint. Kills with the weapon equipped feed XP; level-ups boost damage + scaling. Universal mechanism — stat-gate side effect makes it a class-picker mechanic in practice (Unburdened's 1/1/1/1 lock prevents wielding most weapons). Substrate persistence applies (Wood-craft persists; Hell-craft dies with the weapon). Design: [docs/design/weapon-xp.md](design/weapon-xp.md).
- **Weapon evolution** — branching DAG per weapon family at `config/evolution/{blades,bludgeons,ranged,unarmed,...}.json`. Each `EvolutionNode` has 1+ `EvolutionPath` entries (`target_node` + `min_level` + `material_config_path` + `material_qty` + `sangue_cost`). Family-locked (no cross-family transitions). Evolution uses the imprint-making verb (no workbench). `evolution_bonus` carries forward; XP resets to 1 / 0. Feral acquired-stat tier-thresholds gate unarmed-evolution branches. Substrate-change branches exist (Wood↔Hell crossings). Design: [docs/design/weapon-evolution.md](design/weapon-evolution.md).
- **World containers** — hand-placed lootable objects (pilgrim packs, reliquaries, corpses, ossuaries, niches) with per-instance `loot_table` declared in region JSON. Distinct from enemy drops (materials + sangue only, never weapons) and from the Wood-side chest (player storage). **Most weapons in the game enter inventory through these**, including the descent-stair starting weapon. Per-character-persistent emptied state. Cosmologically: prior-Vagrant Hell-craft residue (broken reclamation protocol) + Wood-craft persistence (substrate outside Hell's accounting). Design: [docs/design/inventory.md](design/inventory.md) *World containers* + [docs/design/crafting.md](design/crafting.md) *World-placed weapons*.
- **Pickups (selva::loot)** — runtime pickup registry: `spawnPickup(world_pos, ItemInstance, source_actor_id, on_granted)` registers a Pickup interactable via selva::interact, attaches it to a corpse (source-bound, follows hips joint, despawns with fade) or sets a static world position (unbound). `tickPickups()` drops source-bound pickups when their corpse vanishes; `hardReset()` wipes all on character switch. `on_granted` callback fires after grant for per-spawn extensions (descent-stair starter dispenser uses it to record per-character emptied state). — [include/loot/Pickups.h](../include/loot/Pickups.h)
- **GatherSpawner (selva::gather)** — Wood-side procedural gather node trickle. ONE unified flow (`config/gather_nodes/wood_forage.json`) maintains `active_cap` total nodes across the Wood; each spawn rolls the flow's `drop_pool` (engine::ecs::WeightedPool) to pick which material instantiates (today: bark_scrap / clay / pale_lichen, weighted 40/35/25). Adding a new Wood material is one entry in drop_pool; no new flow needed. Rejection-sampled placement (Territory check + slope sample + cylinder-collider distance + spacing + bias-away-from-player). Cap+interval loop mirrors FlowSpawner shape but diverges in TWO ways: (1) state lives in PlayerProfile.active_gather_nodes + gather_flows + next_gather_node_id so quit-reload returns to committed state (anti-cheese commit-on-spawn per [[project_anti_cheese_rolls_locked_2026_06_14]]); (2) spawns interactables via `selva::loot::spawnPickup` (unbound, static world position) instead of actors. Ticks globally on wallClock regardless of active region so Wood refills while player descends in Hell. `resetGatherSpawner()` clears PlayerProfile gather state + unregisters interactables, called by both `hardResetWorldForCharacter` and `softResetWorldForCycle`. Per [[project_healing_system_locked_2026_06_14]]. — [include/gather/GatherSpawner.h](../include/gather/GatherSpawner.h)
- **StarterDispenser (selva::loot)** — descent-stair starter weapon spawn. Per-frame gate: `signing_committed` set AND `descent_starter_granted` unset → spawns the class-shaped tier-0 weapon (lead_mace / bone_knife / fang / ampoule) partway down chapel_descent_corridor at t=0.35. On grant, the on_granted hook sets the `descent_starter_granted` flag on the active PlayerProfile, gating future ticks for this character. Per [classes.md *Class-shaped descent-stair starter weapons (LOCKED 2026-06-14)*](design/classes.md). — [include/loot/StarterDispenser.h](../include/loot/StarterDispenser.h)
- **Equipment (engine::ecs)** — slot-keyed equip state per PlayerProfile. Each slot stores the equipped item's stable `ItemInstanceId` (NOT an inventory index — items stay in inventory; equipping just marks which id each slot uses). Slots: right_hand / left_hand / head / chest / legs / feet / accessory_1/2. `engine::ops::inventory::equipItemToSlot(inv, equip, id, slot)` is the canonical equip op; auto-unequips the item from any other slot it occupied. `playerEquipment()` global forwards to the active profile's equipment so UI surfaces stay in sync. Engine-side stays generic (any game can use it). — [engines/engine/include/ecs/Items.h](../../../engines/engine/include/ecs/Items.h) *struct Equipment*
- **Equip UX (Borne sub-page)** — Souls-style slot-first picker. Each slot row is a Selectable that opens a popup of every inventory item that fits there (filtered by ItemDef.category + ItemDef.armor_slot per the `itemFitsSlot` predicate). "(None)" entry unequips. "[equipped]" prefix marks the current slot occupant. Borne sub-page (named for what the Vagrant *bears* — weapons, armor, accessories, scrip) is the **single canonical surface** for both equip ops AND scrip-slot assignment; the inventory detail panel does NOT show Equip or Assign — that would create two ways to do the same thing. Filter rules: hand slots accept weapon / incantation / invocation; armor slots accept armor matching that armor_slot; accessory slots accept accessory; scrip sub-slots accept Consumable. The Borne sub-page ALSO contains an inline TreeNode "Scrip" (the pilgrim's pouch) with `kQuickSlotCapacity` (=5) numbered sub-slots; each sub-slot is its own picker driven by `selva::combat::setQuickSlot` and shows duplicate consumables already-assigned-elsewhere disabled with tooltip. — [src/ui/Screens.cpp](../src/ui/Screens.cpp) *renderPauseVesselBorne*
- **EnemyArchetype** — JSON-loaded archetype: actions, faction, is_npc, skeleton_id, character_path, `mesh_path` / `mesh_path_variants`, `random_face_morphs`, `intangible`, clip overrides per family (idle / walk / death / flinch / hit_react), hurtbox_decls, lockon_points, boss fields (is_boss, boss_name, initial_state, engage_clip, initial_freeze_at_seconds, max_hp_override), spawn_clip + spawn_clip_freeze_at_seconds, transform_target_archetype (drives resolveAppearance lerp), examine_text + interact_range_meters, avoids_hazards, disable_hurtboxes — [include/gameplay/EnemyArchetype.h](../include/gameplay/EnemyArchetype.h). **Authoring workflow (adding a new archetype):** [docs/enemies.md](enemies.md). **Multi-variant mesh contract:** author gender-variant lists in the SAME ORDER across a parent archetype and its `transform_target_archetype`; the mesh_variant_index is stashed at spawn and re-indexed on swap. **Intangibility:** actors sit in the Jolt `INCORPOREAL` collision layer ([`engines/engine/src/physics/PhysicsWorld.cpp`](../../../engines/engine/src/physics/PhysicsWorld.cpp) `namespace Layers`); one code path, no if-checks in the tick.

Merge semantics: child object keys override parent, child arrays REPLACE parent arrays wholesale (`merge_patch`). Used by `larva_aged_feeder` to inherit from `larva_aged`. Depth-limited to 8 to catch cycles.

## Diagnostics

- **CrashHandler (engine::)** — catches fatal SEH faults (access violation, divide-by-zero, illegal instruction, stack overflow), uncaught C++ exceptions, std::terminate. Writes a symbol-resolved stack trace (DbgHelp + `-gcodeview` debug info) to `<save-dir>/crashes/crash-<timestamp>.log` + a one-line summary to `last_crash_summary.txt`. Process exits cleanly via `TerminateProcess` after dump. On next boot, `selva::ui::renderMainMenu` reads the summary + shows a recovery banner above the menu items. Install ONCE very early in `main()` before any subsystem init (catches init faults too). Set save dir + recovery callbacks once SDL pref-path is resolvable. — [engines/engine/include/CrashHandler.h](../../../engines/engine/include/CrashHandler.h)
- **CrashContextScope (engine::)** — RAII helper. Wraps a code block with `setCrashContext("name")`/restore on exit; the dump's `Context:` line names whichever scope was active when the fault fired. Useful around per-frame subsystem dispatch (`renderPickupMeshes`, `tickEnemies`, etc.) so a future fault dump points at the right subsystem without per-frame logging cost. — same header.
- **Build fingerprint** — first line of every selva-oscura.log: `[build] selva-oscura commit=<hash> configured=<ts>`. Lets us answer "which exact binary did this run use?" without stat'ing the .exe after the fact (the .exe gets rebuilt fast; the fingerprint in the log is permanent). Stamped via CMake `SELVA_GIT_COMMIT` / `SELVA_CONFIGURE_TIME` defines.

## Render (high-level entry points only)

- **WorldRenderer** — orchestrates all render passes (shadow → sky → terrain → static meshes → actors → trees → light sprites → UI overlays) — [include/render/WorldRenderer.h](../include/render/WorldRenderer.h)
- **Camera** — third-person + FPV modes, lockon-yaw integration, follow-distance/height/pitch from Tunables — [include/render/Camera.h](../include/render/Camera.h)
- **ShadowPass** — cascaded shadow map; the indoor/outdoor signal (no scene_kind flags per [[real-lighting-doctrine]]) — [include/render/ShadowPass.h](../include/render/ShadowPass.h)
- **SkeletalRenderer** — per-actor skinned mesh draw, bone-palette uniform, per-skeleton mesh registry — [include/anim/SkeletalRenderer.h](../include/anim/SkeletalRenderer.h)
- **PickupSpritePass (selva::render)** — depth-tested world-space pillar-of-light pass for every live `selva::loot::Pickup`. World-up vertical quad billboarded around its Y axis (rotates to face the camera horizontally but never tilts off vertical). Fragment shader gives a hot core + soft horizontal falloff and a vertical taper-to-point (the Elden-Ring drop silhouette — thick at the base, candleflame point at the top). Instanced quad + additive blend + depth test on / depth write off. Distance falloff (kNearDistance / kFarDistance) tuned wide so a drop reads across a Selva clearing — pillar IS the discovery cue at distance, not a close-range "ambient light" wash. Rarity drives pillar height + width + alpha; quality nudges height up at high tiers. Layered on top of any world_mesh, so Wood material pickups carry both the mesh and the pillar. — [include/render/PickupSpritePass.h](../include/render/PickupSpritePass.h)
- **PickupMeshPass (selva::render)** — renders any live `selva::loot::Pickup` whose ItemDef declares a `world_mesh` path (Wood materials today: bark_scrap / clay / pale_lichen) as a static .glb mesh in the world. Process-wide cache keyed by world_mesh path; first spawn loads + uploads, subsequent spawns hit the cache. Per-pickup model = T(world_pos) * R_y(world_yaw); yaw committed at gather-node spawn per anti-cheese, 0 for corpse-bound and authored pickups. Uses the scene shader program (called inside the bind alongside renderEquippedWeapon / renderDoors). The PickupSpritePass pillar is layered ON TOP, so a Wood material pickup shows both the mesh (confirmation when you walk up) and the pillar (cue from across the area). — [include/render/PickupMeshPass.h](../include/render/PickupMeshPass.h)
- **EquippedWeapon (selva::render)** — the player's equipped right-hand weapon as a static mesh parented to the `mixamorig:RightHand` joint each frame. Resolves the equipped item via `playerEquipment().right_hand` → ItemInstance → ItemDef.visual_weapon (a `.gltf` / `.glb` path). Meshes are cached process-wide by config_path (first equip loads + uploads to GL; subsequent equips hit the cache). Joint world matrix from `PoseSampler::jointWorldMatrixWithActor` after setActorPlacement is current. Runs in the scene-shader pass (alongside `renderDoors` / `renderStaticMeshes`), NOT the skeletal pass, because the weapon mesh is unanimated geometry rendered with the scene program. Depth-buffered against the player skin so it composes correctly. v1 has no per-weapon grip offset (mesh origin lands at wrist joint without orientation correction) — adding `grip_offset_matrix` to ItemDef + post-multiplying in `drawEquippedWeapon` is the obvious next polish. — [include/render/EquippedWeapon.h](../include/render/EquippedWeapon.h)

## Cross-cutting patterns

These aren't systems with a header file; they're discipline rules the codebase enforces in multiple places. Listed here so the audit step finds them before duplication risks them.

- **Atomic multi-step UX chains** — chains that span multiple screens / modals (Signing: CharacterCreationScreen → Guide dialog → class picker → commit) MUST commit via ONE terminal flag, not via intermediate flags. Quit-to-desktop mid-chain persists intermediate flags and strands the dialog tree. Today's instance: the Signing chain commits at `ClassPickerScreen::commitClass`'s `signing_committed`; the CharacterCreationScreen commits name + appearance atomically before Playing begins, so the Guide's `guide_open_name_prompt` handler just opens the class picker directly. Per [[project_atomic_signing_chain_2026_06_13]].
- **Named entry points for shared Phase changes** — when N call sites enter the same Phase, the per-case flag setup gets refactored into N named helpers, one per entry kind. Today's instance: `enterPlayingFromNewGame()` / `enterPlayingFromContinue()` / `enterPlayingFromLoadGame()` in Screens.cpp; only NewGame sets `pending_wake_scene`. Per [[feedback_named_entry_points_for_phase_changes_2026_06_13]].
